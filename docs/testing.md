# План и протокол тестирования PawShelter

## 1. Общие сведения и среда тестирования
- **Проект:** PawShelter (WPF / C# / ADO.NET `Microsoft.Data.SqlClient`)
- **СУБД:** Microsoft SQL Server Express (`localhost\SQLEXPRESS`, база данных `PawShelterDB`)
- **Скрипты подготовки БД:** `database/schema.sql` и `database/seed.sql`
- **Цель тестирования:** подтвердить корректность CRUD-операций, фильтрации, бизнес-правил с вольерами и статусами, транзакционной целостности (`SqlTransaction`), валидации пользовательского ввода и устойчивости при ошибках.

---

## 2. Подготовка перед прохождением тестов
1. Выполнить `database/schema.sql` и `database/seed.sql` на экземпляре `localhost\SQLEXPRESS`, чтобы база `PawShelterDB` находилась в исходном состоянии.
2. Запустить приложение `PawShelter` из Visual Studio (`F5`) или через `dotnet run`.
3. Убедиться, что загрузились начальные записи из `seed.sql` (*Барсик*, *Рекс*, *Луна*) и справочники видов и вольеров.

---

## 3. Функциональные тест-кейсы

| ID | Название теста | Предусловия | Шаги выполнения | Ожидаемый результат |
| :--- | :--- | :--- | :--- | :--- |
| **TC-01** | Стартовая загрузка реестра и списков | БД `PawShelterDB` развёрнута и заполнена через `seed.sql` | Запустить приложение `PawShelter` | Главное окно открывается без ошибок; в таблице отображаются активные животные (`IsArchived = 0`) с подстановкой вида (`Species`) и вольера (`Enclosures`); выпадающие списки заполнены |
| **TC-02** | Поиск по части клички | В реестре есть животные *Рекс*, *Барсик*, *Луна* | Ввести в поле «Кличка» значение `Рек` и нажать «Найти / Обновить» | В таблице отображается запись `Рекс`; остальные несовпадающие записи скрыты |
| **TC-03** | Поиск без учёта регистра и с лишними пробелами | В реестре есть животное `Барсик` | Ввести `  барс  ` в поле «Кличка» и нажать «Найти / Обновить» | Запись `Барсик` находится корректно, ошибка поиска не возникает |
| **TC-04** | Фильтрация по виду животного | В реестре есть животные разных видов (*Собака*, *Кошка*, *Кролик*) | Выбрать в фильтре «Вид» значение `Собака` и нажать «Найти / Обновить» | В таблице остаются только собаки (`Рекс`, `Луна` и др. активные собаки) |
| **TC-05** | Фильтрация по статусу | В реестре есть записи со статусами *В приюте* и *На лечении* | Выбрать в фильтре «Статус» значение `На лечении` и нажать «Найти / Обновить» | Отображаются только записи со статусом `На лечении` (например, `Луна`) |
| **TC-06** | Комбинированная фильтрация и сброс | Применены фильтры по кличке, виду и статусу | Нажать «Найти / Обновить», затем нажать «Сбросить» | Сначала применяется комбинация условий, после нажатия «Сбросить» поля очищаются и выводится полный список активных животных |
| **TC-07** | Добавление животного с заселением в открытый вольер | Вольер `К-201` имеет статус `Открыт` и свободные места (`CurrentCount < Capacity`) | Заполнить кличку `Мурка`, выбрать вид `Кошка`, вольер `К-201`, возраст `1.5`, нажать «+ Добавить» | В БД добавляется запись `Мурка`; в рамках транзакции `CurrentCount` вольера `К-201` увеличивается на 1; таблица обновляется |
| **TC-08** | Добавление животного без вольера | Приложение запущено, справочники загружены | Ввести кличку `Снежок`, выбрать `Без вольера`, возраст `2.0`, нажать «+ Добавить» | Запись сохраняется с `EnclosureId = NULL`, в колонке «Вольер» отображается `Без вольера`, счётчики занятости вольеров не изменяются |
| **TC-09** | Граничное значение возраста (`0` и дробное число) | Открыта форма добавления животного | Проверить добавление с возрастом `0` (например, котёнок/щенок до года) и дробным значением `0.8` | Значение `0` и положительные десятичные значения принимаются; отрицательные числа отклоняются |
| **TC-10** | Смена статуса активного животного | Выбрано животное со статусом `В приюте` | Выбрать новый статус `На лечении` и нажать «Сохранить статус» | Статус записи в БД и таблице обновляется на `На лечении` |
| **TC-11** | Перевод животного в статус «Передан» и освобождение вольера | Животное закреплено за открытым вольером (`EnclosureId IS NOT NULL`) | Выбрать животное, выбрать статус `Передан` и нажать «Сохранить статус» | Статус обновляется на `Передан`; в рамках транзакции освобождается место в вольере (`CurrentCount` уменьшается на 1, `EnclosureId` сбрасывается при необходимости) |
| **TC-12** | Архивирование животного и освобождение вольера | Выбрано активное животное (`IsArchived = 0`), при необходимости закреплённое за вольером | Нажать кнопку «В архив» | Устанавливается `IsArchived = 1`; животное пропадает из рабочего списка; при наличии вольера его счётчик `CurrentCount` уменьшается в транзакции |
| **TC-13** | Формирование сводного отчёта | В БД есть животные разных видов/статусов и вольеры | Нажать кнопку «Сводный отчёт» в шапке окна | Открывается отчёт с актуальными подсчётами по видам, статусам и заполненности/свободным местам в вольерах |

## 4. Негативные тест-кейсы и проверка транзакций

| ID | Негативный сценарий | Действия пользователя / тестовое условие | Ожидаемый результат |
| :--- | :--- | :--- | :--- |
| **TC-14** | Пустая или пробельная кличка при добавлении | Оставить поле «Кличка» пустым или ввести только пробелы, нажать «+ Добавить» | Выводится сообщение о необходимости указать кличку; запись в `Animals` не создаётся |
| **TC-15** | Некорректный формат возраста | Ввести `abc` или пустое значение в поле «Возраст», нажать «+ Добавить» | Срабатывает валидация числа; выводится понятное сообщение об ошибке, обращение к БД с некорректным возрастом не проходит |
| **TC-16** | Отрицательный возраст | Ввести `-2.5` в поле «Возраст», нажать «+ Добавить» | Ввод отклоняется валидацией и/или ограничением `CHECK (AgeYears >= 0)`; запись не добавляется |
| **TC-17** | Попытка заселения в заполненный вольер | Заполнить вольер до максимума (`CurrentCount = Capacity`) и попытаться добавить ещё одно животное в этот вольер | Бизнес-правило блокирует заселение; транзакция откатывается (`Rollback`), `CurrentCount` не превышает `Capacity`, выводится предупреждение |
| **TC-18** | Попытка заселения в вольер со статусом «На ремонте» / «Закрыт» | Выбрать вольер со статусом `На ремонте` (например, `Р-301`) или `Закрыт` | Заселение блокируется правилом проверки статуса вольера; данные в БД остаются неизменными |
| **TC-19** | Действие без выбранной строки в таблице | Не выделять строку в `AnimalsGrid` и нажать «Сохранить статус» или «В архив» | Выводится сообщение с просьбой выбрать животное в таблице; падение (`NullReferenceException`) не происходит |
| **TC-20** | Повторная смена статуса уже переданного животного | Выбрать запись со статусом `Передан` и нажать «Сохранить статус» | Срабатывает бизнес-правило запрета изменения статуса переданного животного; транзакция не фиксирует некорректный переход |
| **TC-21** | Недоступность SQL Server Express при запуске или запросе | Остановить службу SQL Server Express или указать неверный сервер в строке подключения | Приложение не падает молча: исключение перехватывается и пользователю выводится понятное сообщение об ошибке подключения к БД |

## 5. Проверка интерфейса и визуального отображения
- **TC-22:** Проверено отсутствие засветки и сливания белого текста при наведении и выделении строк в `DataGrid` (используются тёмно-коричневые оттенки фона и белый текст).
- **TC-23:** Проверено корректное отображение текстовых значений (`DisplayMemberPath="Name"` и `DisplayMemberPath="Code"`) во всех выпадающих списках (`ComboBox`) в открытом и закрытом состоянии.
- **TC-24:** Проверено масштабирование и расположение элементов при изменении размера окна в пределах минимальных размеров (`820x560`).
