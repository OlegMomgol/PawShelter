# Требования и бизнес-логика системы PawShelter

## 1. Назначение и цели системы
**PawShelter** — настольное WPF-приложение для автоматизации учёта животных, контроля заполненности вольеров и ведения жизненного цикла подопечных приюта для животных.

**Цели разработки:**
- Обеспечить единое хранилище данных о животных, видах, вольерах, медицинских записях и усыновлениях на базе **Microsoft SQL Server Express**.
- Исключить ручные ошибки при заселении животных (превышение вместимости вольеров или заселение в закрытые вольеры) за счёт транзакционной обработки (`SqlTransaction`) в слое доступа к данным (`DatabaseService`).
- Предоставить персоналу приюта наглядный интерфейс с поиском, многокритериальной фильтрацией, управлением статусами, архивированием и сводной аналитикой.

---

## 2. Пользовательские роли и сценарии работы
В текущей версии системы реализован единый интерфейс оператора/администратора приюта:
- **Просмотр и навигация:** загрузка актуального списка неархивированных животных с подстановкой читаемых названий видов и кодов вольеров (`INNER JOIN` / `LEFT JOIN`).
- **Поиск и фильтрация:** быстрый поиск по подстроке клички, фильтрация по виду животного и текущему статусу, сброс фильтров в исходное состояние.
- **Приём и заселение животного:** регистрация нового подопечного с выбором вида, вольера (или размещения без вольера) и указанием возраста.
- **Управление жизненным циклом:** перевод животного между статусами (*В приюте*, *На лечении*, *Передан*) и перенос записи в архив (`IsArchived = 1`).
- **Аналитика и контроль:** формирование сводного отчёта по распределению животных по видам, статусам и загруженности вольеров.

## 3. Функциональные требования

| Код | Требование | Описание реализации |
| :--- | :--- | :--- |
| **FR-01** | Просмотр реестра животных | При запуске и обновлении загружаются все записи из `Animals` с `IsArchived = 0`, отсортированные по убыванию `Id`, с объединением таблиц `Species` и `Enclosures`. |
| **FR-02** | Поиск по кличке | Поддерживается поиск по частичному совпадению (`LIKE N'%' + @Search + N'%'`) без учёта регистра. |
| **FR-03** | Фильтрация по виду и статусу | Пользователь может комбинировать фильтр по виду (`SpeciesId`) и статусу (`Status`), а также сбрасывать все фильтры кнопкой «Сбросить». |
| **FR-04** | Регистрация нового животного | Создание новой записи в `Animals` с проверкой заполненности клички и корректности числового значения возраста (`AgeYears >= 0`). |
| **FR-05** | Изменение статуса животного | Обновление поля `Status` для выбранной в таблице строки с немедленным отражением изменений в БД и интерфейсе. |
| **FR-06** | Архивирование записи | Логическое удаление животного (`IsArchived = 1`), скрывающее запись из рабочего списка без потери истории в БД. |
| **FR-07** | Сводный отчёт | Формирование агрегированной сводки (`COUNT`, `SUM`) по количеству животных в разрезе видов, статусов и свободных мест в вольерах. |

## 4. Бизнес-правила и транзакционная целостность

Все критические операции изменения данных выполняются через `SqlConnection` и `SqlTransaction` в `DatabaseService.cs` с обязательным откатом (`tx.Rollback()`) при нарушении условий или возникновении исключения:

1. **BR-01 (Контроль вместимости и статуса вольера при приёме):**
   - При добавлении животного с указанием вольера в транзакции проверяются поля `Status` и `CurrentCount < Capacity` в таблице `Enclosures`.
   - Если вольер закрыт (`Status <> N'Открыт'`) или заполнен (`CurrentCount >= Capacity`), операция прерывается, транзакция откатывается, а пользователю выводится понятное предупреждение.
   - При успешной проверке выполняется `INSERT INTO Animals` и инкремент `CurrentCount = CurrentCount + 1` в `Enclosures`.
2. **BR-02 (Запрет возврата переданного животного):**
   - Если животное уже имеет статус `Передан`, повторная смена его статуса блокируется бизнес-правилом.
3. **BR-03 (Автоматическое освобождение места в вольере):**
   - При переводе животного в статус `Передан` или при его архивировании (`IsArchived = 1`), если за животным был закреплён вольер (`EnclosureId IS NOT NULL`), в рамках той же транзакции выполняется уменьшение счётчика `CurrentCount` (с защитой от ухода в отрицательные значения) и отвязка вольера.
4. **BR-04 (Мягкое удаление / архивация):**
   - Физическое удаление (`DELETE`) из таблицы `Animals` не применяется, чтобы сохранить целостность связей с таблицами `MedicalRecords` и `Adoptions`.

## 5. Нефункциональные требования
- **Платформа и стек:** `.NET` (WPF), язык `C#`, провайдер данных `Microsoft.Data.SqlClient`, СУБД `Microsoft SQL Server Express`.
- **Безопасность запросов:** все SQL-запросы выполняются исключительно с использованием параметризованных команд (`SqlCommand.Parameters.AddWithValue`), что исключает SQL-инъекции.
- **Пользовательский интерфейс:** единая тёмно-коричневая цветовая палитра (`#2C1E16` / `#3C291F`) с высококонтрастным белым текстом (`#FFFFFF`), кастомными стилями для `DataGrid`, `ComboBox`, `TextBox` и кнопок, адаптивной вёрсткой (`MinWidth="820"`, `MinHeight="560"`).
- **Обработка ошибок:** исключения уровня БД и валидации перехватываются на уровне UI (`try / catch`) и отображаются через информативные диалоги `MessageBox` без аварийного завершения приложения.
